# 渲染分层与扩展指南

> 适用版本：v2.3.1 起。  
> 目标：把「捕获 → 处理 → 呈现」拆成三条互不越界的链路，任何一层出问题都不应该
> 变成另一层的隐藏副作用；同时让新增参数/效果只需要改少量明确的位置。

## 1. 为什么拆

旧实现把 DXGI 捕获、LUT 重建、覆盖层窗口、交换链、Present、帧率 OSD 全部塞在
`LutEngine` 一个类里（约 2000 行）。这带来两个直接后果：

1. **多层叠加/效果缺失**：`FilterEngine` 按显示器逐个创建 LUT 引擎，某台显示器
   启动失败时把全局 `kind_` 改成放大镜/伽马，但已经启动的 LUT 覆盖层不会自动拆除。
   同一桌面先被 LUT 处理一次、再被放大镜/伽马处理一次；反向切换时残留的伽马表也会
   叠在 LUT 上。
2. **改一个选项影响另一个**：窗口、捕获、参数上传、LUT 重建、Present 的代码互相
   耦合，修一处很容易碰坏另一条路径；新增参数要同时改网页、宿主、HLSL、JSON，
   漏一处就表现为「界面能拖、实际不生效」或「重启后参数回退」。

现在渲染链路固定为：

```
DesktopCapture  →  SceneSample（每秒一次）
      │ 工作纹理 SRV
      ▼
ColorProcessor  →  LUT / 后处理 / 暗场景权重
      │ 后缓冲 RTV
      ▼
OverlayPresenter →  覆盖层窗口 + 交换链 + Present
```

## 2. 三层职责（只允许通过这些接口通信）

| 层 | 文件 | 负责 | 明确不负责 |
| --- | --- | --- | --- |
| 捕获 | `src/engines/render/desktop_capture.{h,cpp}` | DXGI 桌面复制、固定 BGRA8 工作格式、异格式帧诊断、延迟一帧的场景采样、工作纹理 | 窗口、LUT、交换链、Present |
| 处理 | `src/engines/render/color_processor.{h,cpp}` | `FilterSettings → 44 float 常量缓冲`、64³ LUT 重建限速、中性直通、暗场景自适应权重、单遍像素着色器 | 捕获从哪来、后缓冲怎么呈现 |
| 呈现 | `src/engines/render/overlay_presenter.{h,cpp}` | 覆盖层窗口、flip 交换链、按缓冲身份缓存 RTV、Present(1)、帧率 OSD、捕获亲和性 | 捕获纹理、颜色计算、FilterSettings |

`LutEngine`（`src/engines/lut_engine.{h,cpp}`）只做编排：创建设备、启动三层、
每显示器一条渲染线程、捕获自愈、帧率统计、自检、生命周期。
它不直接改纹理内容。

`FilterEngine`（`src/engines/filter_engine.{h,cpp}`）只做**后端选择与互斥**：
LUT / 放大镜 / 伽马三者任何时刻只允许一个在屏幕上生效。

## 3. 线程模型

- UI 线程：创建/销毁窗口、WebView2、托盘；`FilterEngine::Apply`、`LutEngine::Start/Dispose`、
  `SetFpsDetail/SetOsdText`、`UpdateFpsOsd`。
- 渲染线程（每显示器一条）：`DesktopCapture::Poll/TakeSceneSample`、
  `ColorProcessor::Draw`、`OverlayPresenter::BeginFrame/Present/SetOverlayVisible`。
- 参数跨线程：`ColorProcessor::Apply` 只写带锁的 `params_` 并置 `paramsDirty_`；
  渲染线程在 `Draw` 里限速重建 LUT。不要从 UI 线程直接碰 D3D 纹理。
- 覆盖层窗口操作：渲染线程只能调用 `ShowWindowAsync` / `SWP_ASYNCWINDOWPOS`；
  同步窗口调用会和 UI 线程的 `join()`/模态循环互相死等。

## 4. 后端互斥（防止多层叠加）

`FilterEngine` 的硬规则：

- LUT 路径按显示器创建 `LutEngine`；一旦某台显示器启动失败，**先拆除所有 LUT 引擎**，
  再整体回退到放大镜/伽马。绝不允许「部分显示器 LUT + 全局放大镜」共存。
- 从放大镜/伽马切到 LUT 前，`StopNonLutLayersLocked(true)` 会强制复位放大镜和伽马表。
  伽马表不随进程退出自动恢复，上一次异常退出留下的曲线是「打开滤镜画面发灰」的常见原因。
- 任何低层后端生效前都会 `StopLutEnginesLocked()`；`Reset()` 无条件复位两层低层效果。
- `SetUseDxgi` 不仅比较值，还比较当前后端是否匹配；LUT 曾回退到放大镜后，用户再次
  打开 LUT 会真正重试，而不是被 early-return 卡在「开关是开、实际跑放大镜」。

修改这里时请保持一个不变量：**同一台显示器、同一时刻，屏幕上只有一条颜色处理路径。**

## 5. 新增一个基础参数

1. 在 `src/models.cpp` 的 `FilterParams::All()` 表里加一行：
   - `Key`：网页/桥接参数名（camelCase）
   - `Label`：中文标签
   - `JsonKey`：`profiles.json` 字段名（冻结，不要随意改）
   - `Min/Max/Default`：唯一范围定义
   - `Member`：`&FilterSettings::Xxx`
   - `Advanced`：是否属于仅 LUT 的后处理
2. 在 `FilterSettings` 里加字段（默认值必须等于表中的 `Default`）。
3. 在 `ColorProcessor::Apply` 里把字段映射到常量缓冲槽；如果要新槽，先同步
   `hlsl.h` 的布局注释与 `kParamsFloatCount`，再改 HLSL。
4. `FilterSettings::Equals` 必须比较新字段（保存快照/脏检测依赖它）。
5. 网页不需要改：宿主通过 `init/sync` 下发 `params` 表，`webui2/app.js` 的
   `adoptParamDefs()` 会生成滑块、设置范围/默认值/分组。
6. 如果是高级项，还需要在 HLSL 的 `PostActive` 判断里消费它（否则快路径会跳过）。

> `profiles.json` 的字段名是兼容性契约：`UseDxgi`、`Captureable`、`DarkSceneBoost`
> 等名字即使语义已经变化也不能重命名。新增字段可以，删除/改名不行。

## 6. 新增一个效果

- **捕获阶段的效果**（例如新的场景分析）：加在 `DesktopCapture`，只输出
  `SceneSample` 或帧元数据；不要在此处做颜色处理。
- **处理阶段的效果**：
  - 参数写进 `ColorProcessor::Apply` 的 44 float 布局；
  - 需要邻域采样的放在单遍像素着色器内（保持 `PostActive` 快路径）；
  - 如果每次参数变化都要重算 64³ LUT，放在计算着色器；否则放在像素着色器。
- **呈现阶段的效果**（例如 OSD、边框）：只改 `OverlayPresenter`，不要碰工作纹理。
- 新增效果后跑：
  ```powershell
  .\build.ps1
  .\build\HScreenFilter.exe --selftest
  .\build\HScreenFilter.exe --enginetest=4
  .\build\HScreenFilter.exe --enginetest-cycle
  ```

## 7. 暗场景优化与持久化

- 用户滑块 `DarkSceneBoost` 是 `FilterSettings` 的普通字段：写入 `profiles.json`、
  随配置导出/导入、参与 `Equals` 脏检测。
- 场景自适应权重（0.5..1）是运行时量，**不进 JSON**；由
  `ColorProcessor::UpdateSceneWeight` 根据每秒一次的场景平均亮度维护，只写常量
  缓冲槽 42。槽 41 永远只放用户滑块值，避免「场景一亮权重归零后滑块失效」的自锁。
- `FilterSettings::FromJson` 会用 `FilterParams` 表夹取所有基础参数；旧配置超出范围
  也不会把非法值送进引擎。

## 8. 已知护栏（不要拆）

- **覆盖层固定 `WDA_EXCLUDEFROMCAPTURE`**：`Captureable=true` 只保留 JSON 字段兼容，
  不再生效。覆盖层一旦允许桌面复制捕获，滤镜会抓到自己输出并自反馈全黑，不能靠时序规避。
- **工作纹理不继承捕获源共享标志**：DXGI 桌面复制源带 `MiscFlags=0x2900`（共享 +
  keyed mutex）；工作纹理必须固定 `Usage=DEFAULT / BindFlags=SHADER_RESOURCE /
  MiscFlags=0 / CPUAccessFlags=0`。继承后 `CopyResource` 会静默失败，出现
  「场景探测有内容、工作纹理/输出全黑」。
- **隐藏的 flip 交换链绝不 Present**：`OverlayPresenter::BeginFrame` 检查
  `IsWindowVisible`；这是 v2.0.0-beta 永久卡死的根因。
- **按缓冲身份缓存 RTV**：flip 交换链后缓冲轮转，单槽缓存会退化为每帧创建。
- **按显示器坐标找 DXGI 输出**：`EnumDisplayMonitors` 与 `EnumOutputs` 顺序不一定一致。
- **不做软件帧节流**：节拍交给 `Present(1)`；加软件节流会与 vblank 错相。
- **LUT 重建限速 30ms**：拖动滑块时不要每次 `Apply` 都重跑 64³ 计算着色器。
- **场景探测延迟一帧回读**：`TakeSceneSample` 先读上一轮、再为当前帧排队；
  不要改成立刻 `Map`，那会每秒插一次 GPU 同步点。
- **`SetOverlayVisible` 从渲染线程调用必须异步**：否则 UI 线程 join 时死锁。

## 9. 排查「画风骤变 / 叠加 / 缺失」

1. 看日志 `%LocalAppData%\HScreenFilter\debug.log`：
   - `FilterEngine ... 回退到放大镜/伽马，并拆除所有 LUT 覆盖层`：确实发生过 LUT 启动失败；
   - `覆盖层捕获亲和性`、`覆盖层已隐藏/显示`：检查是否有多层窗口或捕获暂停；
   - `暗场景优化：场景平均亮度=...`：确认权重链路。
2. 确认没有第二个实例：单实例互斥会拦截，但异常残留进程仍可能留下覆盖层。
3. 切换 LUT 开关两次（关→开）：`SetUseDxgi` 会强制重新探测后端；若仍失败，日志里
   会有 `LutEngine Start 失败` 的具体原因。
4. `--enginetest-cycle` 覆盖「隐藏覆盖层后强制重绘」这条最危险的路径。
5. **全黑屏**：先看渲染自检的「输入中心像素」。
   - 输入也全黑、场景探测却正常：工作纹理拷贝失败，检查是否又继承了源纹理的
     `MiscFlags`/共享标志；
   - 输入全黑、且日志里 `Capturable=1`/`WDA_MONITOR`：覆盖层被自己的桌面复制捕获，
     必须强制 `WDA_EXCLUDEFROMCAPTURE`；
   - 输入正常、输出全黑：查 LUT 着色器/后处理参数，而不是捕获层。
